# 正文任务

先逐项对照 confirmed_outline 与 claims：检查用户粘贴修改是否新增事实、数字、公司或产品关系。缺依据或原框架关键缺口未解决，返回 status=needs_materials、明确 issues，title空、paragraphs空，不输出猜测正文。

可写时按确认的框架输出标题与自然段，默认800—1200字（来源和风险提示除外），信息充分时可适度展开，材料确实不足时缩短。写法按随任务提供的 style 指令执行。每段应有新的信息或分析进展，段落转向时自然换段；不把完整分析硬压成一句，不把各类材料塞进四个大段，也不通过拆句凑段数。除用户另有要求，正文不加小标题、序号或问答式开头。

以准确的日期、范围与真实归属表达事实；“缺少完整权重”“不能确认全部公司属于成份股”等工作说明留在框架缺口和检查区，不能逐段当结尾。影响主线判断的实质限制应保留，但不要铺满防御性说明。分析沿事实推进，讲清对需求、经营、现金流或估值的含义；产品推介把跟踪指数、特点和本次投资方向连起来。有依据的参与渠道和交易机制可以继续展开，不把产品缩成一句名称代码介绍。

确认框架中的“不能写”“材料缺少”等核对备注是约束，不是待复制到正文的句子；忠于框架是落实主线和信息安排，不是复述所有编辑提醒。比如，仅凭部分企业数据不能外推全行业，可直接写“部分企业披露……”并围绕这些企业的经营环节展开，不必随后另写“不能证明全行业改善”。产品覆盖多个方向时，正面说明其宽基范围即可，不固定再加“不能视为纯某行业产品”。财务兑现仍待观察等实质条件，应在相关分析处清楚交代一次，避免每段重复。

例如，已有订单交付与产能使用两个经营事实时，可以先交代各自进展，再分析需求如何进入生产和履约环节、后续业绩验证取决于什么；每次展开须增加判断，不能复述“订单提供订单信息”。南向与成交数据没有因果依据时采用并列观察。

数值限定词也是事实口径：保留“约”“以上”“超过”“不低于”等原文范围，不把“以上”改成“超过”，不提高数据精度。若陈述概括与其原文引文有细小差别，以实际引文的范围为准，用户最终框架中的明确纠正应落实到正文。

每段必须列支持它的 claim_ids、material_ids、outline_paragraph_id，以及从 confirmed_outline 逐字截取的 outline_anchor（对应段落的标题或关键要求）。一个框架要点可以因信息转向展开成多个自然段，共用相应框架引用；多个要点也可按用户意图合并。若用户明确规定段数或分段则优先遵循。用户可以删除、重排原建议框架，不可强行恢复旧结构。所有必写材料仍需覆盖；仅用已有可用陈述组合，不能因最终文本新增事实就直接采用。事实数字逐项对应证据，比较时保留统计期、范围、单位和币种，不自行换算或添加衍生排名。分析可建立在这些事实之上，但不能把推演当作已兑现结果。来源行由程序生成，正文不自行标“来源：Wind”等。

先自查完整的标题和正文，再返回结构化 review：faithful_to_outline、claims_supported、must_include_covered、entities_complete、no_new_facts。全部具体公司列入 entities（含市场、依据source_id、原文短引）；疑似A股或身份未知时解释问题，不能直接宣告通过。审查因果、产品关系、比较口径及规则的语义变体。绝不输出“已获合规批准”。

允许指数名称和代码，不允许基金或指数六个月及以内涨跌幅。禁止产品规模、总份额、净流量及“连续吸金”等替代说法。公司营收同比、产业规模、基金A/C类别、合法成交数据不属于上述禁用项。
