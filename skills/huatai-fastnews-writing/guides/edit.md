# 编辑：把初稿实际修成可交付稿

你收到 composing_draft、同一份事实材料、人工确认主线和完整范文。你的任务是实际修改初稿，再返回完整标题、正文和逐段来源。不要只写评语，也不要因初稿已经结构完整就机械保留。

按以下顺序编辑：
1. 主新闻是否清楚且靠前；没有改变本题理解的程序细节是否挤占篇幅。
2. 每段是否推进文章；重复解释、核验口吻和无信息量收尾应当实际删改。
3. 产品联系是否具体、自然，能否用1—2步讲清；说明书式产品介绍改为与主题相关的特点。
4. 用范文校准节奏与表达，但当前事实和V6.4口径优先。文章保持约1100字，不为字数恢复低价值内容。
5. 对照原文检查改稿有没有改变对象、数字、统计期、上限、计划阶段或付款条件。必要边界准确保留一次。

先完成交付正文，再整理独立证据记录 evidence 和检查结果。每条 evidence 指向最终正文段号 paragraph_index（从1起）、source_id，并给出原文中一个连续 quote、它支持的陈述 statement、kind、data_period、supported 和 reason。引文须覆盖对应事实的必要细节；不同位置的引文分列，不拼接成伪原句。程序另行核对原文和数字。每段列出的来源须有对应证据，公开日期由程序从已核对资料取得。

internal_planning_notes 中的统计对象、不可推断事项和产品关系是内部备忘。编辑时检查正文是否把这些备注复述成了“这说明了什么范围”“二者属于不同环节”等重复解释；事实已说清的，直接推进，不为完成框架检查而保留一句总结。产品承接应说清最具体、有依据的交集，不能仅宣告“有关联”或“提供线索”。

陈述可以来自已确认原文中的相关细节，不必出现在旧框架claims中；不引入新来源、范文事实或另一条主线。分析是基于已列事实的必要理解，不新增未证实的行业结论或持仓判断。正文数字及其单位、约数与上下限都须有相应引文。

entities 仅列实际正文、标题涉及且需要判别的具体公司，给出来源及身份；来源标题中的公司不必搬入正文。review 分别核对主线、证据、必写项、实体和材料范围；no_new_facts 表示没有超出本次提供的已确认材料，不是禁止利用原文细节。

editorial_review 简明记录仍存在的编辑问题。changes 简述实际完成的修改。发现问题先修改，再检查最终稿；不能让评语说“应删除”，正文却原样保留。确实无法修好时如实列 issues，不宣称可采用。最终采用和编辑耗时由用户判断。
