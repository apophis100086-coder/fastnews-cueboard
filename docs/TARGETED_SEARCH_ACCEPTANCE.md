# 产品定点联网补搜：2026-09-17 验收记录

本轮在现有产品研究流程中增加来源分流、定向问题、材料身份与增量合并。仍使用本机 Codex / ChatGPT 订阅，程序默认晨扫仍为 13 个元数据入口、0 LLM、不抓全文。原 26 个来源加 6 个细分入口的注册范围未扩张。

## 已交付的行为

- `config/host_source_access.yaml` 逐项记录 32 个入口的宿主搜索和正文读取策略。程序无适配器或曾发生 TLS 故障，不再自动等于宿主不能搜索。FDA、CSIA 等可进入相应产品计划；明确停用、登录/授权要求和范围未确认的路径分别保留限制及原因。
- `config/product_search.yaml` 给四只产品配置来源事实问题。588710 包含订单、客户导入、扩产、资本开支、材料和工艺阶段；517120 区分临床、受理、批准、授权与支付。补充关键词不能替换核心问题。
- 产品任务先使用已有列表和同一期次已存公开片段，再定点发现、补依据、归并。复用片段带取得时间、指纹、来源身份；人工笔记、私有上传稿和产品私有文件不进入宿主输入。
- 新报告保留 `claims`、短片段、实际引用 URL、声称的原始出处、时间字段、工具引用及缺项。只有适配器提供的实际工具文本能建立“片段可定位”；模型自述、打开动作或搜索摘要均不产生 verified Fact。
- 同一结构化事件按主体、动作、对象、阶段、日期与已知统计期归并。没有足够身份信息时采用保守匹配；同主题、不同阶段或不同统计期不强行合并。重复来源不计为新增独立事件。摘要改写仍可能需要人工判断是否同一事件。
- 用户点击加入或“合并新增依据到原线索”后，材料进入现有候选池。合并追加依据，保留原标题、摘要及原证据。旧人工决定、旧导出保持原样；重新保存选择后，新增依据进入新一版 MD/JSON。
- 失败或超时保留旧候选、草稿、证据，并可显示上一份可用报告。无新增时允许空结果。失败未返回 usage 时记录未知，不能算作零消耗。

未新增数据库迁移、模型 API、外部写作流程或第二套网站系统。`sources.yaml`、`topic_taxonomy.yaml`、`products.example.yaml` 保持原始字节。

## 预算和边界

沿用 8 条查询计划、最多 20 个新来源、单任务 300 秒、每天 12 次尝试及 24,000 字符公开输入限制。一次关键补读包含在当前宿主任务内；`product_search.yaml` 的 `evidence` 可调低到 1—3 个事件、每事件 1—2 页，没有额外叠加第二轮。

应用强制限制本地输入、结果数量、任务次数和超时；站点搜索/补读计划传入宿主指令，返回结果再按来源权限检查。当前 CLI 不提供每个内部请求的强制域名拦截接口，也没有完整页面内容 trace，因此不能把计划上限或来源覆盖自报当作已经独立测量的内部执行结果。

同一期次已存材料用于减少重复查询，但无法证明宿主没有再次读取相同页面。验收报告区分重复 URL、材料指纹复用与不可观察的实际重复请求。本次结果没有复用输入片段；缓存复用、跨报告补证和失败保护由离线回归覆盖。
