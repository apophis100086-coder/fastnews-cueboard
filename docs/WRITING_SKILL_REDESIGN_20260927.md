# 项目内置写作 Skill 重做

基线为 `dabef96`，独立分支 `codex/writing-skill-redesign`。本轮处理固定材料到成稿的质量差距，晨报与召回仍沿用前轮未通过的验收结论。

## 改动与边界

- Skill 按框架、成稿、编辑分阶段加载。写作先做新闻取舍，产品联系用必要事实解释；证据记录不再主导起草任务。V6.4及用户明确口径保留，旧规则被替换。
- 起草读取确认框架、已读原文或连贯摘录、产品依据及最多两篇完整公开已发稿。范文可以跨产品学习写法，但不作为本期事实。私有、标题级、不完整或截点外范文不进入模型；省略与原有截断明确记录。
- 起草和编辑使用同一份材料，两次宿主调用共享480秒总期限与390秒模型处理时间，起草最多240秒。立即保存第一版，再编辑；编辑失败时保留第一版但禁止作为完成稿导出。
- 编辑结果使用独立证据记录，允许原文中的相关细节进入成稿；取消逐字框架锚点。保留原文、日期、数字、单位、范围、必写项及产品口径检查。
- 已选材料和确认门槛不变，沿用原版本表保存两版、输入、实际修改、模型设置及耗用。旧稿不重写，旧契约继续可读。技能版本包含编辑指引。

## 验证方法

`tools/run_writing_comparison.py` 只在固定 `data/v64_acceptance_20260926/live.db` 中运行。基线输入和旧稿在本轮修改前冻结，正式库与验收库各做一致性备份。

三个主题为恒生科技、半导体设备与创新药，仍使用9月25日23:59:59截点。旧流程按冻结的原始输入和指令回放，新流程使用同一组已确认事实；两套流程均通过现有订阅使用 `gpt-6-sol / high`。两步调用的差异、完整范文和原文上下文属于本次流程改动。不会把这个实验解释为已经复现ChatGPT窗口设置。

每次运行显式确认测试框架，不代表编辑批准；不改正式库选材，不读取独立召回清单，不重新抓取新闻，不覆盖前次尝试。所有原始稿、编辑前后版本和失败记录留在本地 `data/writing_skill_redesign_20260927/`。测试代码与文档入Git，原始数据不入Git。

功能检查与实际稿件质量分别记录。事实遗漏、重点位置、产品关系、重复及文风由原始输出逐篇评审；实际修改时间和采用结论保留给用户，不能由程序状态或模型自评分代替。

## 当前进度

首轮真实对照发现：起草与编辑确实产生了不同版本，但统计口径说明仍容易被当成正文内容。进一步将与原模板逐字一致的“分析”“产品承接”备注从正文框架中分离，标为内部编辑备忘；任何用户改动的行都保留在主要写作输入中，原确认文本不改写。

PDF引文仅有换行差异时，程序回定位到原始连续片段再核对，保留模型原始返回；不会跨省略段拼接，也不会把两行独立数值合成一个新数字。原先失败的恒生科技稿另存程序复查结果，正文哈希不变。创新药稿出现了模型重组断句的真实引文问题，不能用排版容错放过。

功能已通过首轮完整回归和正常推送检查。最终测试数量、三题运行结果与编辑观察在真实回放完成后补记；实际编辑时间和采用结论仍待用户。
