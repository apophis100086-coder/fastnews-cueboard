# 框架反复生成失败：历史参考说明被误当成本期材料

基线 `e40a111`，独立修复分支 `codex/fix-outline-context-validation`。

## 真实原因

正式库最近三次恒生科技框架任务均已返回模型结果，总耗时分别为348.56、275.67、207.17秒，没有触发480秒总时限，也未被每日次数限制拒绝。

三次都在保存前报出“框架必须说明每条已选材料的安排或未用原因”。模型已经逐条解释全部所选与补查材料，但还在 `dispositions` 内加了一项输入中真实存在的 `product_context.published_history` 历史范文，明确说明其只供参考。旧校验要求安排清单与当前材料集合完全相同，因此将这项额外说明视为异常，整份框架未写入版本表。

根因是程序没有区分“本期事实材料”和“已提供的历史参考说明”。本轮不通过去除事实校验、放宽来源限制或再次消耗模型调用修复。

## 修复

- 框架仍要求覆盖所有本期材料。输入中确实提供的历史稿或完整范文，其使用说明单独保存为 `context_dispositions`，页面独立展示。
- 未知材料、重复编号、遗漏本期材料仍拒绝；历史稿不能进入段落材料编号或事实陈述，不能借此把旧事实写成新消息。实际缺失的原文、日期、实体、必写项和产品关系仍作为待补依据保留。
- 框架指引明确安排清单的范围。成功结果也保留模型原始返回与可观察轨迹，便于将格式处理与模型输出分开核对。
- 新增受限的维护恢复工具，只接收这一已知校验错误的完整原始返回。恢复前核对选材版本及补查核对记录，追加不可变框架版本；不改原失败任务、来源核实状态和用量，不调用模型，重复执行不重复写版本。
- 页面注明框架来自原返回恢复，区分“框架已显示、依据待补”与运行失败。原始规则、原失败记录和人工编辑区保留，不自动确认或成稿。

## 真实恢复与保护

先以SQLite一致性备份保存正式库。将三次保存的真实失败结果在内存副本中回放，均得到可展示的框架，分别有4、5、3段；均保留真实缺口，状态为 `needs_materials`，未将其改标为可以成稿。

正式库仅恢复最近一次：9月26日19:21:13截点的恒生科技期次。数据库逐表比较，仅 `fn_writing_versions` 从2条增加为3条，其余表内容一致，原失败任务和人工选择未变，完整性检查通过。新增模型调用为0，每日次数仍为1、上限仍为null。

该题仍缺主事件的可靠原始依据，以及能支持产品联系的有效资料；所选部分来源无法独立读到原文，保留其原有访问状态。此次修复解决运行误拦截，不冒充资料补全或写作质量验收。

本地备份、三次原始失败、回放结果、正式恢复版本、数据保留检查及页面截图位于 `data/outline_failure_20260928/`，不入Git。已在真实看板载入对应期次，确认恢复提示、框架与待补依据可见，正文按钮仍保留确认与证据门槛。
