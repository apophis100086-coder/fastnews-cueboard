# 日期晨检改版验收｜2026-09-15

## 解决的问题

原“刷新结果”只重读数据库，“检查来源”只做连接探测，新闻候选还依赖建立本期。用户无法直接按日期查看晨检信息。

本次增加独立日期阅读页：选新闻日期后直接显示已存信息；点击“获取当天信息”实际按该日采集。新闻标题、列表摘要（来源提供时）、来源日期、原文链接和数量在首页显示。产品期次及人工素材篮移入独立的“选题与交接”区域。

## 实际改动

- `fastnews/daily.py`：无需 Edition 的只读日期查询；报道日期优先、已知首次公开日期回退、未知日期独立，历史修订版本及缺档提示。
- `fastnews/pipeline.py`、`fastnews/__main__.py`：新增 `collection_date` 与 `scan-morning --date`；北京时间日界，未来日期拒绝，实际采集时刻保留，不改默认增量晨扫进度。
- `fastnews/server.py`：`GET /api/daily?date=YYYY-MM-DD`、按日期采集任务及入队前校验。
- `fastnews/static/`：日期、今天/昨天、获取、只重读、来源诊断的清晰分工；可见的条数、失败和未接通状态；异步错误捕获、快速切日期防旧响应覆盖。
- 新增日期查询/采集测试、服务端回归及实际前端脚本交互测试；更新使用指南。

没有修改原26来源、21晨扫标记、9主题、4只产品路由，没有新增数据库迁移或删除数据。
