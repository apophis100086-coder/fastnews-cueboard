## 现在能做什么

`research-product` 把固定事件池和本期已授权材料整理为一份可追溯的研究记录。首次公开时间未知的线索会进入待核验研究；它们不会因此变成截点内可用事实。截点外信息及无法重建的后来修订版本仍单独列出。

程序提供 `none` 和明确隔离的 `fixture` 搜索、模型接口。当前没有已授权、已实测的商业搜索、模型或 Wind 运行时接口。默认运行不会调用这些服务，也不会使用开发 Codex 会话。模型未接通时只保留规则路由、实际取得的资料与缺口，报告显示“未做语义评估”“未完成全网补漏”。

公开网页正文读取是独立能力。默认不读取正文；根 CLI 的 `--fetch-public-text` 会启用有域名、robots、响应大小和请求预算限制的公开读取器。它只处理清单内已发现的文章链接，实际可读性逐篇记录。网页读取成功不代表事实已核实、首次公开时间已确定或产品相关性已评估。搜索摘要始终是线索，不能进入已读原文和 Fact。

## 命令

在项目根目录运行：

```powershell
python -m fastnews research-product 513130 --offline --summary
python -m fastnews research-product 513130 --edition-id <已经创建的EditionID> --summary
python -m fastnews research-product 513130 --edition-id <已经创建的EditionID> --fetch-public-text --summary
python -m unittest tests.test_research -v
```

`--offline` 使用独立合成数据库。合成 provider 返回的是测试提议，不能作为真实搜索或模型结果。没有 Edition 的研究只生成研究视图；冻结 Edition 才能连接本期事实、比较记录和人工素材篮。其他产品代码仍为 513530、588710、517120。

## 执行顺序

1. 读取本地固定事件池，优先处理路由匹配项，并在 12 个总名额内保留少量探索项。未知首次公开时间的材料保留待核验状态。
2. 读取本期授权文件；按预算获取短名单公开原文（仅当读取器显式启用）。同页跨事件复用，保留各自事件关系。
3. 搜索 provider 若配置且获授权，使用公开产品代码、配置主题定向检索。私有材料正文不会拼入搜索词。结果仍标为 `search_snippet_only`，未读原文的缺口保留。
4. 模型 provider 若配置且获授权，只接收已有证据及受限上下文。私有材料还需单独的本轮外发许可。输出必须通过字段、实际引用 ID、原文范围与摘录检查；模型无权确认 verified、人工采用、成稿或发布。
5. 返回已有结果、未处理事件 ID、预算和来源缺口，并保存 run。没有足够材料时可以少于三条。

模型抽取结果是 `pending` 的事实提议；有效引用检查不等于核实经济事实。已存在的候选评估由 M3 契约再校验，模型不能写入 Decision。

## 预算怎样工作

数值来自 `config/runtime.defaults.yaml` 的 `second_round`，均为试跑初值。

| 项目 | 每次研究上限 |
|---|---:|
| 事件 | 12 |
| 正文资料 | 20 篇 |
| 单事件正文 | 4 篇 |
| 搜索请求（含失败和重试） | 8 |
| 模型请求（含失败、修复和重试） | 4 |
| 模型输入 token | 24,000 |
| 模型输出 token | 6,000 |
| 金额上限 / 币种 | 尚未配置，null |

每个调用最多两次尝试。模型调用前以 provider 的最大输入、输出额度预留预算，SQLite `BEGIN IMMEDIATE` 保证同一 run 的并发请求不能同时花掉最后一个名额。成功或失败后有真实 usage 才结算；usage 未知时保留预留，不将超时或失败报为零 token。已知 usage 小于预留会归还差额。

报告分别显示实际测得的 `input_tokens`/`output_tokens` 和保守计入预算的 `accounted_*`。缺实际值为 null。未调用显示 `not_called`；调用后费用不全则显示 `unknown`，不会显示零元。设置金额上限后，无法提供最大费用估算的请求会在调用前停止。

正文失败也计入访问请求。跨事件同页只访问一次，已授权文档和同页证据在上下文中复用。预算耗尽返回 `partial`，不丢掉已处理候选、不自动追加额度。

已知来源政策不允许读取时，在请求前记录 `fulltext_skipped`，不算网络请求或正文预算。`fulltext_requests` 是实际provider尝试，`fulltext_read_document_count`是取得或复用正文数，`fulltext_policy_skipped_resource_count`是策略跳过数；三者不混算。关闭 `llm_allowed_when_configured` 会阻止模型调用及模型评估缓存复用。

本次真实FDA读取2篇；后续同一期复跑复用2篇缓存、0新请求，其余10个不允许全文的候选在调用前跳过。来源链已存，未自动形成Fact或Decision。实际证据见实施状态内链接。

## 缓存与审计

- 缓存隔离 `live`/`fixture`，键包含材料 hash、产品、Edition/截点、路由版本及规则内容、画像版本、历史快照、提示词 hash 和 provider/model 版本。
- 模型缓存依据实际读到的内容 hash。证据或模型版本变化时重新评估；命中缓存后仍校验引用。
- live 正文和搜索默认缓存有效期为一小时，provider 可指定 `cache_ttl_seconds`。过期会重新读取；fixture 默认稳定缓存。缓存复用会明确计入 `cache_hits`，不冒充本次联网。
- `fn_research_runs` 保存输入版本、预算、状态、结构化结果；`fn_provider_calls` 保存预留、尝试序号、结算和有限错误码；`fn_call_cache` 保存已验证的结果或实际读取正文。
- 不在调用日志中保存请求提示词、任意异常全文、密钥或私有文件正文。授权材料正文与研究缓存只留在本地数据库。

## 尚需外部条件

商业搜索与模型需要用户实际服务、凭证、价格和外发范围授权后才能接通；Wind 仍需用户授权导入或后续获授权接口。正文读取能力须以真实运行报告中的逐篇成功/失败为准，不能从配置来源数量推断。评分、产品结构、历史稿件完整性及真实语义效果不能用 fixture 测试代替。
