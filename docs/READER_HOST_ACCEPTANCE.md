## 使用方式

1. 打开 [本地看板](http://127.0.0.1:8765/)，选择新闻日期。
2. 点 **管理网址与模型**。可以另建个人方案、添加网站或公开 RSS / Atom、选择晨报/领域板块、分类、启用或停用。各方案保存自己的来源偏好，本机新闻库和工作期次共用。
3. 晨报有两种操作：**获取当天信息**只读已适配的公开列表，不调用模型；**生成分类总报 · Codex**会使用 Codex 登录额度补充检索、去重和分类，摘要附出处。原站入口一直可以直接打开。
4. 细分领域按政策、港股、医药、科技、农业、金属等类别筛选。原清单共26项，其中6项晨报、20项领域来源；网站可同时归入多个类别。
5. 进入产品选题，选择产品和新闻使用截点，再点 **检索该产品线索**。产品报告综合范围内的已存列表、此前晨报研究摘要及额外联网检索，最多10条。
6. 若要让产品推荐使用今天的信息，点 **截至上方新闻日期**；默认截至昨天时，今天的新消息不会纳入该期。采集日期与写稿截点分别保存。
7. 对感兴趣的推荐点 **加入人工候选池**，再自行选择主事件、保存和导出。加入候选不会自动选题，AI摘要也不会自动转为已核实事实。

报告保留生成时间和信息截点。相同材料、来源方案和期次在5分钟内复用结果；当天时钟变化不会触发无意义的重复调用。切换期次不会误用另一份期次的缓存。

## 使用哪一份模型额度

### Codex：已经真实验证

通过官方 `codex exec` 启动独立后台任务，运行前检查 `codex login status` 为 ChatGPT 登录。与其他 Codex 任务共享账号额度，没有配置或使用模型 API Key。

这不是复用当前聊天的上下文。程序只发送所选公共网址、公开列表摘要、带出处的既有研究摘要以及产品观察规则。用户导入的私有文件、历史稿正文、私有持仓资料不进入这一请求。任务在独立临时目录执行，关闭 shell、插件和多代理；不提取、复制或记录登录令牌。

官方说明：[非交互运行](https://learn.chatgpt.com/docs/non-interactive-mode)、[登录与计费模式](https://learn.chatgpt.com/docs/auth)。页面读取已存数据及 Windows 登录启动均不会触发模型。

### WorkBuddy：入口已适配，当前未通过实测

发现本机捆绑命令行入口，已实现受限工具与结构化输出的调用路径。当前实测没有返回可解析报告，因此页面标为 **待验证命令行授权**，不能报告为已接通，也不能保证该账号的桌面额度可由命令行使用。需要 WorkBuddy 官方支持的登录和额度授权可用后再验收。程序没有回退到 DeepSeek 或其他付费 API。

## 预算及可核验范围

本地任务配置在 `config/reader.defaults.yaml`：每天最多12次宿主任务（所有方案共用，失败也计数）、单次300秒、公开材料输入（含来源配置）最多24000字符、产品最多10条、晨报最多40条、最多20个新增出处、每条最多4个引用。服务同一时间执行1个后台任务。

原固定来源二轮仍受12事件 / 20全文 / 每事件4篇及原请求预算约束。模型任务的公开材料也按候选和文本长度限制。订阅 CLI 内部会进行多轮模型调用，本地无法对其内部请求数和token给出逐请求硬上限；程序记录宿主返回的实际用量、缓存量和耗时，不把未知费用写成0。提示词对联网查询次数和网页读取量提出上限，但宿主的内部执行由宿主管理，不能等同于应用自身的硬网络预算。

`web_actions` 是 CLI 可观察的联网动作数。返回链接未在日志中出现可对应的打开记录时，一律标为宿主检索线索；即使模型说读过原文，也不会自动标为已核实事实。来源覆盖说明是宿主报告，不等于程序逐篇独立核验。
