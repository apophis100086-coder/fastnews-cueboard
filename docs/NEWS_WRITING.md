# 第三步：选材与快讯

五只产品使用相同的工作流。背景交接包仍可导出；写作不会改变晨报、产品检索、候选池的原有人工选择。

## 使用顺序

1. 在人工候选池勾选本次材料，按需要排序、设置主事件和“必须体现”。补充事实请填来源；表达偏好选“写作要求”，不会作为事实使用。保存选择。
2. 点击“生成写作框架”。模型只接收本次已选材料、选中的补充、主线说明和本次反馈。先取得可比对的出处片段，再返回主线、标题方向、段落要点、材料安排、建议及缺口，不写正文。
3. 输入意见，点击“按意见修改框架”。每轮保留旧版本。关键依据不足会阻止正文；不影响当前写法的可选补料不会阻断。
4. 如需补料，展开“按缺口补搜”，检查并修改公开检索问题后发起。结果回到产品线索，必须人工采用、保存并更新框架，才进入写作输入。
5. 将满意版本放入最终框架编辑区，或自行粘贴并修改。点击“确认此框架并生成初稿”。用户的最终文本决定段落安排；新增事实与数字依然要对应证据。改变已保存选材后，旧框架需要重新整理。
6. 初稿以正文为主，逐段来源折叠；通过检查后可复制标题、正文和来源，或下载 Markdown / JSON。风险提示独立复制，缺失的正式产品备注单独提示。

“重新检查这版初稿”用于程序误拦截修正后的复查，保存为新版本，不改正文、不消耗模型任务，沿用原语义检查。技能或规则发生变化时，此操作不能替代新的模型判断，需要重新确认框架并生成新版。旧稿始终可查。

正文默认约800—1200字，以信息量决定实际篇幅与自然段数量。没有固定四段要求；框架按独立进展、分析关系和产品推介需要安排段落，正文也可以把一个框架要点展开成几个有来源的自然段。材料少时允许短稿，避免重复扩写。生成期间可以继续人工选材、编辑、保存、导出和切换产品；结果只写入发起任务所属期次，完成不覆盖最终框架编辑区。

2026-09-19 的样例学习补充在 `skills/huatai-fastnews-writing/guides/style.md`。它同时用于框架和正文任务：分析说明事实如何影响需求、经营、现金流或估值；产品推介说明跟踪指数、策略特点或参与方式为何与本次主题有关。可由新闻引出产品，再用后续自然段展开具体特点，不能只剩名称代码或“提供观察视角”。通常采用连续自然段，来源与风险提示另列。近期已发表稿件仍不能覆盖现行禁用规则，旧数据和旧产品资料不会自动进入新稿。

## 证据与检查

“选中”不等于“核实”。陈述清单保留来源编号、原文片段、公开日期、统计期、陈述类型和检查结果。研究摘要、搜索摘要、模型自报引文不能单独作为原文。程序读取公开HTML、文本及PDF；PDF最多读取20页，无法提取文字的扫描件提示补充资料，不执行OCR猜测。

读取仍受robots、登录、站点授权、停用来源和私网保护约束；单个来源失败保留缺口。日期来自实际取得的发布元数据、发行人PDF送出日期、金融界文章日期URL，或已导入原始资料的声明日期；日精度不能冒充截点前的具体时刻。媒体转引按实际取得的媒体记录，不改标直接来自Wind。

框架模型与正文模型均执行语义判断。正文阶段关闭自由联网，只能使用最终框架和通过依据检查的陈述。程序再检查引用映射、公开日期、数值与单位、必写材料、已知A股名称、短期收益和产品资金等规则。语义判断仍可能出错；状态名称是“规则检查通过”，不是合规批准。

`config/writing_entities.yaml` 是有出处的已知A股名称补充表，含若干A/H身份，不是完整证券主数据。表外公司仍需模型逐项给出身份与依据，未知身份不能通过。正常指数/基金代码、产业经营增速、成交额和市场南向资金与禁用项分开检查。

风险模板在 `config/writing_risk.yaml`，冻结到稿件版本。已有科创50、港股红利、创新药的有来源风险概括；科创半导体设备与恒生科技暂缺产品专属模板。所有产品的最新正式风险等级、完整法律备注和费率仍提示补齐，不从旧文章套用。

## 版本和数据

迁移007新增写作任务、不可变版本表；不重建旧表。框架、确认框架、正文分别有版本ID、父版本、产品期次、截点、选材版本、来源指纹及技能/规则版本。没有确认框架或选材发生变化，正文接口拒绝执行。旧稿可以查看；规则版本变化后旧稿不直接作为新的通过检查复制稿导出。

选材草稿与框架编辑区各自按工作区、期次保存在当前浏览器本机。不要清理浏览器存储来恢复页面。已确认框架和生成版本进入SQLite；数据库和本地导出不上传GitHub。

每次框架或正文默认一个已授权宿主任务，共享480秒总截止、模型最多450秒、至少30秒收尾。检索与写作合计每日12次（含失败尝试）；选材与来源上下文上限24000字符（不含宿主自身指令开销），超过预算显式报错，不悄悄丢掉必写项。不同产品共用一个重型后台任务，网络等待不持有写事务。支持停止；重启后未完成任务显示中断。

## 接口

接口沿用本地CSRF和同源保护，请求体均为JSON：

| 接口 | 主要输入 | 返回 |
|---|---|---|
| `POST /api/writing-outline` | edition_id、decision_revision、reader_profile、request_id；修改时加parent_version_id、feedback | job_id |
| `POST /api/writing-confirm` | edition_id、decision_revision、outline_version_id、text、request_id | 确认框架版本 |
| `POST /api/writing-draft` | edition_id、decision_revision、confirmed_version_id、reader_profile、request_id | job_id |
| `POST /api/writing-export` | version_id | artifact_type、markdown、risk_notice、trace |
| `POST /api/writing-recheck` | version_id、request_id | 程序复查的新版本；不调用模型 |
| `GET /api/edition?id=…` | 期次 | writing.versions / writing.runs |
| `GET /api/job?id=…` | 任务 | 状态、进度、开始及截止时间 |
| `POST /api/job-stop` | job_id | 停止请求状态 |
| `POST /api/explore` | 原字段及writing_context.outline_version_id | 补搜任务；仅发送用户可见公开问题 |

写作请求ID在数据库中幂等；相同ID不同内容报错。接口不接受任意模型指令路径；运行时只加载仓库技能与版本化配置。修改意见仅进入当前版本，不改写公共技能。
