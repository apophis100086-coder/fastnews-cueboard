# 第三步：选材与快讯

2026-09-29 起采用 `direct-newsroom-v2`。用户明确取消框架环节；旧框架、确认记录和稿件保留，新任务不制造人工确认记录。

## 使用顺序

1. 在左侧候选池勾选材料。可以指定主新闻、必写项，在右侧填写重点或写作要求；不指定主次时，模型在已选材料内判断。
2. 点击“生成快讯初稿”。页面先保存当前选择，保存冲突时保留本机内容并说明原因，不启动错误版本。重复点击不会启动两个任务。
3. 后台补充公开资料、起草、实际编辑并保存。相关补充新闻可自主采用，仍须核对原文与本期截点。可选资料失败不阻断；主新闻或必写项无法核实会返回具体缺口。运行中可停止、切换页面或继续编辑，任务结果写回原期次。
4. 审阅初稿，复制完整稿件或下载 Word。逐段来源显示机构、标题、发布日期和必要的数据期，不显示网址。原文链接和核验详情在“查看依据”展开区，追溯文件单独下载。
5. 可在页面中修改并另存新版本，或填写意见让 AI 修改。人工文字先保存在本机，保存后进入数据库；模型原稿保持不变。人工新增文字标记待核对，不沿用旧的检查结论。

初稿、未完成编辑的起草稿和待核对稿均可查看、复制或下载，状态明确区分。程序通过不等于编辑采用，实际采用与修改时间由用户或带教反馈。

## 实际加载的写作输入

入口为 `skills/huatai-fastnews-writing/SKILL.md`。每次任务加载共用规范、阶段指引以及对应的产品指引，保存全部文本和版本哈希。恒生科技强调产业与商业化；科创半导体强调景气、扩产和设备材料需求；红利系列强调分红、利率、现金流与成员差异。

本机 `data/writing_samples/library.json` 记录13篇授权样例的原件、提取文本、分类、日期和哈希。运行时选两篇完整同类样例，优先最新格式与相近写法；事实与范文分开，历史数字和样例错码不能进入当期稿。原件、提取文本和生成稿都不上传 Git。新电脑需单独导入授权样例：`python tools/import_writing_samples.py "样例根目录"`，目录下包含恒生科技、科创半导体和红利全家桶三个分类文件夹。

输入保留新闻连贯原文，不以零散引文替代全部正文。主新闻、必写资料和完整范文优先；超出容量时按整篇省略可选来源并记录，关键材料过长则提示具体缺口。输入容量96000字符，预留12000字符供编辑结果，不能静默裁掉主新闻。

正文目标约1100字，不固定段数。先写重要变化，再以有效事实推进；产品关系通常一至两步讲清。编辑模型必须返回实际修订的全文，处理重复、空泛收尾、核验口吻和生硬产品承接，保存起草版、编辑版和修改记录。

可选目录为恒生科技513130、科创半导体设备588710、红利全家桶、创新药517120、科创50（588090）。系列内部标识 `dividend_family`，无单一基金代码，默认七只成员：510880、512890、561580、513530、520890、561630、561450。资料按成员隔离，不能合计为一只基金。旧513530期次继续可读，目录覆盖层不改原三份配置。

本次明确放开有依据的指数介绍及规模、份额、净流入等精确产品数据。其他 V6.4 要求保留：标题正文不写 A/H 具体上市公司名与股票代码，不写禁止的短期业绩；计划、预测和统计范围准确表述。正常基金和指数代码不按股票代码误拦。新旧口径通过流程版本区分，不全局放宽历史稿检查。

## 联网、截点和时限

默认现有订阅入口 `gpt-6-sol / high`，记录实际模型与档位。每日应用任务次数不限；账号服务方额度仍按实际情况报告。

一次直接生成共用900秒：资料准备与自主补搜450秒，起草240秒，编辑180秒，保存30秒。阶段不重置总时限；提前完成可提前交稿。补搜取消旧的8查询/6来源限制，按材料充分程度和剩余时间安排；程序新增全文读取20篇、每事件最多4篇。每份PDF仍有20页提取上限，超出和未读内容明确记录。

新闻默认检查截点前7个自然日；较早材料可作有日期的背景。新建期次默认当前时间，历史期次不漂移截点。来源单独失败后转向合法替代；不绕过登录、付费、验证码、robots或已停用权限，不把搜索摘要当原文。

起草与编辑使用同一批已核对材料；自主联网集中在前置研究阶段，新增来源随任务保存，不覆盖人工选材。编辑失败、停止或超时保留已经保存的起草稿，显示“编辑未完成”。

## 检查与版本

事实、口径、编辑质量分开记录。事实引文、实体、数字单位与约数、原文日期和截点逐项核对；编辑建议和非关键格式问题不抹掉整篇稿件。媒体转引保留实际取得媒体，不改标直接查询 Wind。

每版保存产品、期次、选材版本、父版本、来源、Skill 哈希、模型设置和输入快照。选材、本机写作意见、人工改稿按工作区、方案和期次隔离。不要通过清空浏览器存储恢复页面。数据库使用一致性备份，不删库重建。

## 接口

接口沿用本地同源及 CSRF 保护，请求体为 JSON。

| 接口 | 主要输入 | 返回 |
|---|---|---|
| `POST /api/writing-generate` | edition_id、decision_revision、reader_profile、request_id；可选parent_version_id、feedback | job_id，无confirmed_version_id |
| `POST /api/writing-save-edit` | version_id、text、request_id | 独立人工修改版本 |
| `POST /api/writing-export` | version_id | markdown、word_base64、checks、trace |
| `GET /api/edition?id=…` | 期次 | writing.versions、runs、task_budget |
| `GET /api/job?id=…` | 任务 | 状态、进度、实际截止时间 |
| `POST /api/job-stop` | job_id | 停止请求状态 |

旧 writing-outline、writing-confirm、writing-draft、writing-recheck 接口保留原兼容规则。新页面不调用框架接口。请求编号幂等，相同编号不同内容报错。修改意见只用于本次任务，不改变共用 Skill。

历史框架修复与旧成稿验证分别见 `OUTLINE_CONTEXT_FIX_20260928.md`、`NEWS_WRITING_ACCEPTANCE.md`。当前功能与真实成稿验收见 `DIRECT_DRAFT_20260929.md`。
