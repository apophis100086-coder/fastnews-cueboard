# 第三步：选材与快讯

五只产品使用相同的工作流。背景交接包仍可导出；写作不会改变晨报、产品检索、候选池的原有人工选择。

## 使用顺序

1. 在人工候选池勾选本次材料，按需要排序、设置主事件和“必须体现”。补充事实请填来源；表达偏好选“写作要求”，不会作为事实使用。保存选择。
2. 点击“生成写作框架”。模型接收本次已选材料、选中的补充、主线说明和本次反馈；开启补查时按下面的公开检索约束发现相关新消息。先核对已有出处，整理框架后再独立读取新增原文，返回主线、标题方向、段落要点、材料安排、建议及缺口，不写正文。
3. 输入意见，点击“按意见修改框架”。每轮保留旧版本。关键依据不足会阻止正文；不影响当前写法的可选补料不会阻断。
4. 生成框架默认勾选“补查与主线相关的最新公开消息”：在同一次模型任务检查本期截点前7个自然日，最多8次公开搜索、6份新增出处，搜索上限为模型任务指令，并记录可观察到的工具轨迹，不冒充对宿主内部调用的硬限流。新增资料作为框架建议单列，核对原文后随最终框架由用户确认，不改动已保存的人工选材。关闭该选项或方案关闭联网时只用已有材料。仍需进一步补料，可展开“按缺口补搜”，检查公开问题后发起；这条独立补搜路径的结果回到产品线索，人工采用、保存并更新框架后才进入写作输入。
5. 将满意版本放入最终框架编辑区，或自行粘贴并修改。点击“确认此框架并生成初稿”。用户的最终文本决定主线和必写内容，行文可以合并或展开建议段落；已确认原文中的相关细节可进入正文，新增陈述与数字仍须对应证据。改变已保存选材后，旧框架需要重新整理。
6. 一次点击后后台先起草、再编辑，保存两版原始输出及实际修改记录。交付稿以正文为主，逐段来源折叠；通过检查后可复制标题、正文和来源，或下载 Markdown / JSON。编辑未完成时展示已保存的起草稿及原因，不能导出为已完成稿件。风险提示独立复制，缺失的正式产品备注单独提示。

“重新检查这版初稿”用于程序误拦截修正后的复查，保存为新版本，不改正文、不消耗模型任务，沿用原语义检查。技能或规则发生变化时，此操作不能替代新的模型判断，需要重新确认框架并生成新版。旧稿始终可查。

保存新选材后，旧初稿继续可读，但不能复制、下载或通过程序复查恢复为本次稿件；需要按当前选材更新并确认框架。每次导出也会应用当前程序检查，避免旧的“通过”状态绕过修复。程序现在同时核对标题的单位、币种，以及陈述、正文、标题的常见约数与上下限口径；例如“90%以上”不能变成“超过90%”。

正文采用 V6.4，目标约1100字，不固定段数。首段交代明确变化，随后用独立事实推进，产品关联通常用1—2步讲清。分析与产品承接可留空，不能为每段强行增加机制解释。材料不足返回具体缺口；正文与轻量润色在同一个用户任务内分两次模型调用完成，不增加人工确认步骤。生成期间仍可选材、编辑和切换产品；结果只写入发起任务所属期次，不覆盖人工编辑区。

运行时按阶段读取技能入口、共用写法和对应的框架／成稿／编辑指引，保存实际内容和版本哈希。编辑指引变化也会更新技能版本。V6.4 替换旧版“每段展开分析、一路解释到盈利估值、独立介绍跟踪指数”的要求。旧定期报告退出默认写作素材；产品名称、代码与有效定位可以使用，底层指数只作内部核对。资料日期、发布机构、原文标题和链接放在逐段来源区。

## 证据与检查

“选中”不等于“核实”。陈述清单保留来源编号、原文片段、公开日期、统计期、陈述类型和检查结果。研究摘要、搜索摘要、模型自报引文不能单独作为原文。程序读取公开HTML、文本及PDF；PDF最多读取20页，无法提取文字的扫描件提示补充资料，不执行OCR猜测。

读取仍受robots、登录、站点授权、停用来源和私网保护约束；单个来源失败保留缺口。日期来自实际取得的发布元数据、发行人PDF送出日期、金融界文章日期URL，或已导入原始资料的声明日期；日精度不能冒充截点前的具体时刻。媒体转引按实际取得的媒体记录，不改标直接来自Wind。

框架模型与后台编辑模型执行相应语义判断。成稿、编辑阶段关闭自由联网，使用同一组已确认的连贯原文、产品依据，以及最多两篇完整公开已发稿范文。范文单列，只学习表达，不能作为本期事实依据；优先同产品，其次相关产品，均核对截点。必写与主新闻优先保留，容量不足按整篇省略可选材料并明确记录；关键材料超长时返回具体原因。正文不再要求逐字框架锚点，编辑返回独立证据记录，程序继续核对引文、日期、金额和范围。检查分别记录事实、口径和编辑质量：标题与正文不出现A股及港股具体上市公司、底层指数名称代码或精确的产品规模、份额、净流入量值；有出处和时间区间的连续增持趋势可以使用。新闻主次、产品关系、重复机制、空泛收尾及说明书式产品段另有语义评审，不只靠禁用词。程序通过不代表可直接采用；真实修改时长与编辑认可由人工填写。

`config/writing_entities.yaml` 是有出处的已知A股名称补充表，含若干A/H身份，不是完整证券主数据。表外公司仍需模型逐项给出身份与依据，未知身份不能通过。正常指数/基金代码、产业经营增速、成交额和市场南向资金与禁用项分开检查。

风险模板在 `config/writing_risk.yaml`，冻结到稿件版本。已有科创50、港股红利、创新药的有来源风险概括；科创半导体设备与恒生科技暂缺产品专属模板。所有产品的最新正式风险等级、完整法律备注和费率仍提示补齐，不从旧文章套用。

## 版本和数据

迁移007新增写作任务、不可变版本表；不重建旧表。框架、确认框架、正文分别有版本ID、父版本、产品期次、截点、选材版本、来源指纹及技能/规则版本。没有确认框架或选材发生变化，正文接口拒绝执行。旧稿可以查看；规则版本变化后旧稿不直接作为新的通过检查复制稿导出。

选材草稿与框架编辑区各自按工作区、期次保存在当前浏览器本机。不要清理浏览器存储来恢复页面。已确认框架和生成版本进入SQLite；数据库和本地导出不上传GitHub。

一次框架或正文任务共享480秒总截止，资料准备最多60秒、模型处理合计最多390秒、预留30秒收尾。正文采用两个顺序调用：起草最多240秒，编辑使用剩余模型处理时间，第二步不重置总时限。起草返回后立即保存不可变版本；编辑失败、停止或超时均保留它并标记编辑未完成。页面区分起草、编辑进度，最终稿可展开查看实际修改和原稿。

框架补查仍共用原有资料核对时间及20页预算。检索与写作每日上限保持取消（max_tasks_per_day=null）；运行次数继续记录，宿主账号自身限额仍由服务方管理。一次正文任务记录两个宿主调用及分别耗用，不能把未知用量记成零。写作输入上限48000字符，起草输入预留编辑所需空间，不静默截断关键资料。不同产品共用一个重型后台任务，支持停止；已有成果与人工编辑保留。

## 接口

接口沿用本地CSRF和同源保护，请求体均为JSON：

| 接口 | 主要输入 | 返回 |
|---|---|---|
| `POST /api/writing-outline` | edition_id、decision_revision、reader_profile、request_id；可选supplement_latest（默认true，尊重方案联网开关）；修改时加parent_version_id、feedback | job_id |
| `POST /api/writing-confirm` | edition_id、decision_revision、outline_version_id、text、request_id | 确认框架版本 |
| `POST /api/writing-draft` | edition_id、decision_revision、confirmed_version_id、reader_profile、request_id | job_id |
| `POST /api/writing-export` | version_id | artifact_type、markdown、risk_notice、trace |
| `POST /api/writing-recheck` | version_id、request_id | 程序复查的新版本；不调用模型 |
| `GET /api/edition?id=…` | 期次 | writing.versions / writing.runs / writing.task_budget；版本另含supplemental_research、supplemental_materials、source_evidence |
| `GET /api/job?id=…` | 任务 | 状态、进度、开始及截止时间 |
| `POST /api/job-stop` | job_id | 停止请求状态 |
| `POST /api/explore` | 原字段及writing_context.outline_version_id | 补搜任务；仅发送用户可见公开问题 |

写作请求ID在数据库中幂等；相同ID不同内容报错。接口不接受任意模型指令路径；运行时只加载仓库技能与版本化配置。修改意见仅进入当前版本，不改写公共技能。


## 两步写作结果的兼容

新版 content.format_version 为 newsroom-v1。content.pipeline 记录 complete 或 editing_incomplete、起草版本ID、修改记录和材料覆盖；content.raw_article 保留编辑原始返回，content.evidence 保存独立核验记录。现有接口和段落来源展示保持兼容，旧版契约继续可读和复核，不改写历史正文。模型输入与两步输出保存在本地运行记录，不进入Git。编辑未完成的起草版本不能通过程序复查冒充已完成编辑。
