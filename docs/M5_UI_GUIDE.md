## 旧版功能记录（2026-09-15）

看板已经可以展示程序实际取得的来源标题和链接，查看已读材料，保存人工选择，并导出带来源的交接材料。最终选哪条、采用哪些事实、怎样写稿，仍由使用者决定。

截至本轮验收，**4 个来源已实测能读取公开列表元数据**：TrendForce、工信部、国家数据局、FDA。原配置中 FDA 不参加晨扫，因此点击默认晨扫实际读取其中 **3 个来源**。原 26 源仍完整显示；其余来源的失败、受限或未接通状态不会被隐藏。列表范围和历史回填并不完整，详见 [M2 来源报告](M2_SOURCE_REPORT.md)。

**搜索、模型、Wind 接口目前均未接入。** “整理本期线索”会整理已有事件、已取得材料、规则路由和缺口；不会因此完成语义评分、全网补漏或自动核实每一条事实。原产品画像是观察规则，不是实时成份股或持仓资料。

## 启动与打开

在项目根目录运行真实数据看板：

```powershell
python -m fastnews serve --port 8765
```

随后打开 [本地真实数据看板](http://127.0.0.1:8765)。默认使用 `data/fastnews.db`。终端需保持运行，按 `Ctrl+C` 停止服务；页面不会自行部署到互联网。

若要单独体验合成测试流程，在另一个终端运行：

```powershell
python -m fastnews serve --offline --db data/fastnews.fixture.db --port 8766
```

打开 [本地合成测试看板](http://127.0.0.1:8766)。顶部会显示“合成测试 · 不是真实新闻”。点击晨扫使用离线样本；来源探测和真实公开正文读取不可用。测试库与真实库不能混用，合成材料也不能导入真实库。

可以用 `--db` 指定其他已有数据库。程序保留库内数据并核对模式，不能把同一个数据库一会儿当真实库、一会儿当测试库。

## 先按日期看信息（2026-09-15 更新）

首页的“新闻日期”默认为今天，可以选择其他日期或点“昨天”。切换日期直接显示本地已保存的条目，无需建立本期。点击 **获取当天信息** 才会按所选日期向已接通来源补取公开列表；日期采用北京时间日界，今天截至实际扫描时刻。

完成后，页面直接显示该日已存条数、本次新增篇数、成功读取的来源，以及失败/未接通数量。标题、来源日期、列表摘要和原文链接在首页可见。发布日期未知的条目独立列出，首次公开未知保持未知；所有列表元数据仍待核验。

| 按钮 | 作用 |
|---|---|
| 获取当天信息 | 实际采集所选日期的公开列表条目，更新日期列表 |
| 重读已存信息 | 只重新读取本机数据库，不发起新闻采集 |
| 重新检查来源连接 | 诊断来源连接，完成后展开来源状态，不新增新闻 |
| 进入选题与交接 | 展开产品、期次、人工素材篮及导出工作区 |

按日期补取与默认增量晨扫的进度分别管理，不会把日常晨扫游标退回旧日期。历史补取只覆盖目前列表中仍可见的信息，不等于完整历史快照。已知晚于所选日的修订会回退已有旧版本或列为缺档，未知修订时间会标出不确定性。

## 阅读后整理选题

### 1. 展开选题与交接，建立本期

阅读首页条目后，需要整理稿件材料时，点击 **进入选题与交接**。展开后再设置产品和本期；首页新闻日期不会因切换期次而改变。

选择产品、本期日期和新闻使用截点，点击 **“建立本期”**。原四只产品均保留：513130、513530、588710、517120。建立后，所有主事件和事实默认未选；列表第一条也不会被自动采用。

“本期”（Edition）是一份冻结的工作范围：保存产品、新闻截点、行情截点，以及建立当时的画像、评分、输出规则和已导入产品/历史快照。它让以后重看这次选题时，可以知道当时使用了什么依据。

**采集窗口与新闻使用截点独立。** 程序可以采到今天早上的报道，但“新闻使用截点”若为昨天末尾，这些内容仍在截点外或待核实时区，不会自动成为昨天可用的事实。

“行情截点与产品资料”可以展开填写，每行一项，例如：

```text
HK=2026-09-14@用户已核对的行情日期
```

该例仅展示输入格式，应替换为本次真实行情日期及依据。**允许留空**，此时明确标为行情截点未知；政策等非行情线索仍可整理，市场数值需要补齐行情日期、统计期和口径后才能作为可用事实。程序不会根据工作日或减一天猜交易日历。

### 2. 整理、阅读，人工比较线索

点击 **“2. 整理本期线索”**。左侧可查看全部时间分区，或分别看截点内、时间待核实、截点外、历史版本不完整。点击线索标题只打开详情，不等于选为主事件。

右侧“事实与来源”集中展示首次公开、报道、统计期、实施、采集等不同时间，以及来源链、产品关系、历史增量和缺项。首次公开未知时会直接显示未知，报道日期和抓取时间不会补作首次公开日期。

需要补充材料时点击 **“补充线索”**，可上传或粘贴本地材料。已读正文可在 **“查看已读材料 / 手工摘录原句”** 中展开：

1. 从该份材料复制完整原句到输入框；
2. 选择“来源报道 / 数据表述”“已公告的未来计划”或“预测或估计”；
3. 点击“按原句建立事实条目”。

程序检查原句是否能在该版本正文中定位。摘录仍保留实际读取来源、版本与日期；建立成功不等于经济事实已独立核实。数字若缺指标、单位或市场/产品范围，也会保留待补状态。结构化数字资料宜通过带完整字段的 JSON 导入，格式见 [M3 材料指南](M3_EDITORIAL_GUIDE.md)。

若需要读取网页正文，可在 **“用量、研究缺口与运行记录”** 中显式勾选“本次二轮研究读取已允许来源的公开正文”，再整理本期。该操作受来源访问许可及 12 个事件、20 页正文、每事件 4 页预算限制。逐篇成功或失败会记录，读取成功不自动产生事实。默认晨扫仍为 0 次模型调用、不抓全文。

### 3. 保存人工素材篮，再导出

在候选卡上手工选择 **“选为主事件”**，勾选需要的事实。可以选择第二条或其他候选，也可以从不同事件选补充事实，不要求凑满三条或固定段数。

“人工素材篮”里可以上移、移除事实，填写可选的主线说明，或清除主事件。点击 **“保存选择”** 后，页面显示已保存版本号。主线说明留空时，交接包会保留“主线说明未补”，不会代替用户生成结论。

随后点击 **“3. 导出交接材料”**，页面显示两个下载链接：

- **Markdown 交接材料**：供后续写作窗口阅读；
- **JSON 来源追溯包**：保存事实 ID、来源、日期、规则版本和人工决定记录。

导出内容已同时落地到本机，下载入口只读取登记过的导出文件。导出是材料快照；后续刷新或原文更正不会暗中改写旧导出。

尚未保存主事件时不能导出。只有待核实主事件、没有可用事实时，可导出选题意向包，但可用事实区为空，并明确提示不能据此成稿。待核实、冲突、截点外及受限产品数值均不进入可直接用于正文的事实区。

## 草稿、保存与刷新

页面上的手工改动先作为本浏览器、本数据库、本期的草稿保存。刷新结果、整理研究以及重新载入页面会保留该草稿。**草稿不等于已保存的选择**：出现“有本地草稿 · 尚未保存”时，需要点击“保存选择”才能导出当前版本。

已保存选择存入 SQLite，不依赖当前页面是否打开。研究刷新只更新候选和资料，不覆盖已选主事件、事实顺序或主线说明。

如果另一个页面已保存新版本，旧页面不能直接覆盖它。页面会保留旧草稿并提示版本冲突，可以使用“恢复已保存选择”重新读取后编辑。后台晨扫、来源检查或研究正在运行时，服务会阻止新的保存及其他写操作，完成后继续；已有草稿保留。

候选卡“上移”调整当前浏览器的展示顺序；素材篮“上移”调整的是人工选中事实的交接顺序，需保存后进入导出。

## 导入资料的范围

目前页面支持 **UTF-8 JSON、Markdown、TXT**，单个上传或粘贴内容不超过 2 MB。PDF、图片、Excel 和 Word 的解析入口尚未接通，不能把上传格式清单理解为都已支持。

普通正文只存为已读材料，不会自动抽取为事实。填写“原始 URL”保存出处，不会自动打开该链接。文件及粘贴内容留在本机；网页文字中的操作指令和 HTML 标签按资料原文处理。

产品结构需使用包含对象类型、结构日期、公布日期和证据片段的 JSON。历史稿件需保留真实发表日期，以及只有标题、部分正文或完整正文的程度。**先导入结构与历史，再新建本期**，新材料才能进入本期冻结快照；已经建立的旧期次不会被偷偷更改。

实际产品结构、正式历史稿件和 Wind 材料尚未提供时，看板保留缺项。仅填写声明来源为 Wind，不会把媒体转引或任意文件变为直接 Wind 数据。

## 怎样理解状态

| 页面提示 | 实际含义 |
|---|---|
| 元数据可采集 | 已取得标题、链接和页面提供的日期等；不等于读过正文 |
| 已读取公开正文 / 已读取本地材料 | 程序实际保存了该版本内容；不等于所有表述已核实 |
| 时间待核实 / pending | 首次公开、证据、数值口径等仍有缺项，不能直接用于正文 |
| 有明确归属，未独立核验 / reported | 有实际材料和定位，引用时须保留来源及报道归属 |
| 截点内 | 时间检查允许继续核验；不能单凭这个标签认定事实已核实 |
| 历史版本不完整 | 后来修订或旧版本缺失，不能把现在的页面当作当时资料 |
| 缺项，不计算 | 六项评分未齐，程序保留 null；不是低分，也不影响人工选择 |

负面或相反材料不会因不利产品推广被自动隐藏。南向总量可以是港股市场配置线索；没有去向证据时，不能改写为专门买入红利或科技。

2026-09-15 在本地开发环境完成了以下实际交互检查。涉及人工选择、HTML 显示和导出的演示使用明确标记的合成资料，未将它们算作真实市场结果。

| 保存后再次整理本期研究 | 人工选择保持不变 |
| 导出人工已选材料 | 出现 Markdown / JSON 下载链接，文件实际落地 |

另有 19 项服务端离线测试，覆盖本地 Host/Origin/CSRF、上传与密钥拒绝、禁止任意服务端路径读取、测试/真实模式隔离、后台任务挡写、人工选择顺序与版本、登记导出下载等。测试采用内存 HTTP 请求流，不进行联网：

这些结果证明本轮检查过的交互与服务边界可工作。它们不代表已经完成十个真实交易日的选题效果验收，也未验证真实模型建议质量、全来源覆盖或节省人工耗时的目标。后续试跑记录方法见 [M6 试跑指南](M6_PILOT_GUIDE.md)。
