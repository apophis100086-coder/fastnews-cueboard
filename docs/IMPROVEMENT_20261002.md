# WorkBuddy 基线改进：开发、试用与验收

本轮在第三个目录“快讯AI看板 改进实验版”开发。以 WorkBuddy 的当前工作文件建立基线，包含未提交改动与新增直连模块。原 Codex 和 WorkBuddy 目录保留。基线提交 b69e260；业务数据库另以 SQLite 一致性备份保存，实验目录使用副本。诊断资料在本地 data/backups 保存，凭据未复制，运行资料不进入 Git。

## 实施次序与当前行为

1. 先保存基线和数据，再统一工作区、启动、停止与回写身份。
2. 稳定智能体步骤衔接、取消、重启及失败保存，保留人工选材。
3. 更新晨报范围、产品观察和写作规则，完成定向和全量检查。
4. 从已提交源码制作独立试用包，真实 WorkBuddy 与人工质量评审另行记录。

实验版在 8787 运行；原 WorkBuddy 仍使用 8767。config/workspace.yaml 是实验版启动、检查、停止与打包共用配置。移到中文、含空格或其他名称的目录时，身份按实际数据库绝对路径重新计算。端口已有另一个实例时拒绝接管。每次启动只展示已存资料，不自动采集或调用模型。

智能体直连任务总时长不限，由用户在页面停止；请求、网页、搜索和输入容量预算仍有效。普通 CLI 模式保留其原有期限。直连任务对外 deadline_at 为 null；为兼容既有非空数据库列，内部用空字符串保存，不伪造未来日期。新响应绑定工作区、任务、步骤和输入哈希，重复、过期或跨目录回写被拒绝。重启时旧请求标为中断，不自动重放；已保存材料与中间稿保留。

新稿流程为 direct-newsroom-v4-agent：补搜、起草、编辑兼核验、程序检查及保存。旧稿按各自保存的实际步骤解释；只有存在独立核验记录时才称为独立核验。编辑兼核验由同一智能体执行，程序检查只覆盖已实现的出处、日期、数字与结构规则；不能称为逐字事实验证。收到智能体响应不等于原文已核实；智能体自行填写的工具记录和模型名称分别保存为自报信息，不升级为独立联网证据。

## 三部分改进

晨报主列表按近两个自然日组织，七日时间线单列背景。包含宏观、境内外市场、资金、科技、医药和其他行业；同事件报道由既有事件归并处理，旧报道进入背景，缺口继续展示。列表采集默认零模型、不给晨扫增加全文抓取；AI 总览由用户触发。

产品检索沿用已实现的观察变量、七日近期材料与更早背景窗口，要求解释 why_now、阶段及出处。关键词负责路由，不能据此认定持仓、受益或资金去向。五个产品入口保留。

config/editorial_style.yaml 保存共用及产品专属规则。首轮参考本地13篇认可样例：恒生科技5篇、半导体设备4篇、红利全家桶4篇。每次起草加载两篇相关完整例稿；风格档案保存样例编号、日期、哈希及规则版本，旧数字不能作为新事实。固定公司文字仍由模板组装。调整规则会改变技能指纹，旧规则生成的稿件需重新审阅。

## 在 WorkBuddy 试用

在 WorkBuddy 打开实验目录，按项目内 .codebuddy/skills/fastnews-dashboard/SKILL.md 操作。双击一键启动.cmd，网页地址为 http://127.0.0.1:8787/。先检查来源方案和直连配置，选择产品或材料，再触发晨报、产品检索或写作。在 WorkBuddy 说“处理看板任务”；智能体使用 tools/agent_bridge.py 的 status、pending-writes、claim 和 respond 顺序处理同一任务。具体响应格式见 AGENT_BRIDGE.md。

导出前查看待核对项、数据口径与人工选材版本。旧选材对应稿件不能作为当前稿导出。停止任务由用户操作；重新启动可见已存历史稿。验收通过后再切换日常入口，原 WorkBuddy 继续作为回退依据。

## 真实业务验收

工程测试使用合成材料，结果不能代替真实稿件采用率。真实检索使用独立验收库和冻结截点；评审重点事件清单放在检索工作区之外，搜索/写作阶段不得读取答案。生成报告后再将 news_cutoff、items、gaps 保存成 JSON，用 tools/recall_acceptance.py 对比清单中的 event_id、aliases 或 source_urls。它记录字面召回、疑似重复、遗漏及覆盖缺口，语义匹配需人工复核；重要遗漏修正后另存复验记录，旧结果保留。

tools/quality_acceptance.py init data/acceptance/quality_20261002 建立三类各五个案例槽位，不生成或认可任何稿件。题目必须未用于调教。完整记录已通过或真实失败的试验，不能删除失败后只统计重跑成功。capture 以只读方式取得稿件及冻结输入；register 冻结案例并记录题目独立性；review 只登记实际人员提供的六项判断和编辑分钟数。固定模板不计入新闻正文评分。15篇全部评审后，至少每类4篇、总体12篇通过才达标；未评审的采用率为 null。

代码交付、离线测试、服务启动、WorkBuddy 智能体响应、真实来源核实、人工采用是分别记录的状态。交付结果和剩余验证见本地 data/acceptance/工程验收.json；同题前后稿需要真实运行后保存，目前不能用合成测试稿替代。

## 验证与维护

相关测试覆盖工作区身份、重复及过期回写、停止后迟到响应、历史流程、无限期限、晨报日期边界、风格输入和人工验收门槛。交付另运行全量 Python、前端及提交源码隔离检查。原三份配置继续逐字校验。试用包包含批准用于此项目的样例、模板及运行依赖，排除业务库、账号凭据、原始诊断日志和稿件导出。

本轮只建独立本地分支和提交，无远程推送。后续 Codex 与 WorkBuddy 使用实验版这一份主代码；切换前仍需人工验收，代码版本及数据备份分开保管。
