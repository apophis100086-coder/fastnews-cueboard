## 诊断与修复

正式库最近一次领域采集的20个来源中，4个已实现来源均报 `public_dns_failed`，15个 `adapter_not_connected`，1个 `source_terms_manual_only`。这是三种不同情况。原来依赖单个 `1.1.1.1` DoH 节点，实测 TLS 握手超时；本机系统 DNS 又返回 `198.18.*` 假地址，不能放宽私网检查来解决。

`fastnews/network.py` 增加受限的公共解析节点切换、故障短期冷却与 DNS TTL 缓存。默认公开解析使用阿里公共 DNS，Cloudflare 两个节点作为备用；保留旧配置模式。连接保持公开 IP 固定、TLS 主机名/证书验证；瞬时 TLS 中断在原重试上限内换 DNS 返回的下一个公网地址。证书无效、私网、安全检查、robots 和 4xx 拒绝不重试绕过。

端点依据：[Cloudflare 公共地址](https://developers.cloudflare.com/1.1.1.1/ip-addresses/)、[Cloudflare JSON DoH](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)、[阿里 DoH JSON API](https://www.alibabacloud.com/help/tc/dns/httpdns-doh-json-api)。没有新增密钥或付费调用。

`source_health.py` 合并最近一次列表采集、连接检查和产品固定源研究的时间，区分已连接、窗口无条目、未接入、访问受限、网络故障、解析故障。旧晨检错误不会覆盖较新的研究成功结果。技术错误码放入详情，可重试来源提供单独重试按钮；服务端验证当前方案启用且已有适配器。
