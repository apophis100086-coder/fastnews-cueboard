# 产品依据与已发稿回流

2026-09-26 起，已导入且明确标为公开的产品资料会进入产品检索和写作框架；公开历史稿用于对照旧主题与新进展。此前导入能力只负责存储，没有接入这两个环节。

## 资料准备

- 产品 JSON 使用 `import-product-data` 的既有契约。记录 `product_code`、`source_url`、`published_at`、`data_as_of`、`snapshot_type` 和逐字可定位的 `excerpt`。支持 `product_identity`、`index_methodology`、`index_constituents`、`fund_holdings`、`target_fund_holdings`、`business_segment`。编制范围与实际成份分开保存。
- 已发稿 JSON 通过 `import-history` 导入；`publication_time` 是核实后的发布日期，不能仅由文件名推断。本轮增加可选 `source_url`。只有标题时标 `title_only`，不能据此宣称正文使用过哪些事实。标题明确标出另一个ETF代码时，导入会拒绝错误归档；未出现代码并不代表程序核实了产品身份，仍需人工核对。
- 本地原稿、修改稿及尚未确认已发布的文档继续为 `private_local`。仅将已核对的公开材料显式标为 `public`；是否读取了原文、来源归属及实际取得方式仍保留原记录，不因标为公开就变成已独立核实的事实。

```powershell
.\.venv\Scripts\python.exe -m fastnews import-product-data data\reviewed-product.json --product-code 513130 --privacy-class public --db data\fastnews.db
.\.venv\Scripts\python.exe -m fastnews import-history data\reviewed-publication.json --product-code 513130 --privacy-class public --db data\fastnews.db
```

缺省仍是私有，仅在本机保存。三类导入命令现均接受 `--privacy-class`；公开产品和历史稿还必须有来源URL，才会通过本模块进入宿主输入。不要将本地私有资料加上一个公开URL来冒充公开文件。

## 运行方式

1. 先备份并导入资料，再创建新的产品期次。期次会冻结截点内的产品快照和历史稿ID；给数据库补资料不会悄悄改写旧期次、用户选材或已确认框架。
2. 同类产品资料取最近资料时点的一个版本，每次最多三个类型；已发稿取最近两篇，每篇最多700字符，并标记是否截断。没有可用公开依据、没有结构资料或没有已发稿时，输入会保留具体缺口。
3. 产品检索把产品依据用于解释关系，历史稿用于判断增量。引用产品依据的事件必须同时有新闻来源；产品依据单独存入 `product_relationship`，不参与新闻事件指纹，避免所有引用同一招募书的新闻被误合并。看板的“产品关联依据”可展开查看公开资料、资料时点与待核对解释。纯产品资料不会成为自动推荐的新事件。
4. 写作仍须先有人工选中的新闻事实。产品参考材料以 `product_reference` 身份附在框架中，默认不是必写项；逐项来源可定位，资料时点在返回记录中保留。历史稿不会成为写作 claims 的事实来源。用户确认门槛保持不变。
5. 单页公开资料读取上限从600,000字节改为配置中的2,000,000字节，最高允许4,000,000字节，以容纳常见产品PDF。仍最多读取PDF前20页、沿用原页面数/时限/robots/重定向/地址规则，未读部分不能冒充全文。

## 校验和回测

`validation_audit` 记录模型原始条目数、实际保留数及各条未展示原因。无效引用、截点外资料仍会拦截；“0条”不等于未搜到信息。新增离线测试覆盖隐私、冻结截点、最新版本、历史摘要、错误产品代码、来源完整性、产品与新闻引用的分离及基准定义误判。

真实回测必须与正式库分开，共享当天任务预算，不能靠重建数据库或重复配置绕过上限。先保存自动检索结果，再单独记录人工补漏、选材与回测确认；回测确认只用于验证程序，不代表真实编辑批准。不同日期、不同选材的稿件只能比较文风和机制，不能计算同日完整召回率。未找到完整对照集合时，不宣称“全网无遗漏”。

产品结构仍需要定期补充适用于截点的成份、权重或持仓披露。本轮保存的法律文件和指数定位不能替代最新持仓，也不提供Wind授权。
