# V1来源方案与V0.1编辑方案：整合决定

状态：V2开发默认方案。用户明确原则优先；下表“V2补充”是本次设计建议，试跑后可调整，不冒充源文件原文。

| 项目 | 来源交接V1 | 编辑方案V0.1/用户要求 | V2处理 |
|---|---|---|---|
| 最终决策 | TOP3＋备选 | 尽量不替用户决定 | 保留少量候选比较，默认未选择；仅人可写入采用操作；分数可折叠 |
| 数据架构 | 固定源晨扫→产品后二轮 | 前版偏产品输入后搜索 | 以来源窗口的两阶段架构为骨干，后接编辑评估/素材篮 |
| 来源范围 | 26入口，21晨扫 | 先用已有网站 | 26项原样保留，不把新需求静默变成新增爬虫站点 |
| 能力状态 | YAML给模式/部分入口 | 要实际可用 | 新增运行覆盖层；全部从needs_probe开始，不声称已经实测 |
| 产品范围 | 4产品示例 | 3产品重点试点 | 4项都保留；前三只优先完整验收，创新药保持可加载及可研究 |
| 评分 | 0—5相关性/证据/来源/新颖等 | 40/25/20/15、0—4档 | V1公式只做路由；V0.1框架作编辑试跑分；证据/来源独立，不混合累加 |
| 强制阈值 | 未定义 | 不让分数替代人 | 无自动采用线；不按80分裁决；缺项显示null而非造分 |
| 准备度 | 未单列 | 不以能凑四段评判新闻 | 独立记录材料用途和缺口；一段强事实可以做主事件 |
| 时间 | 17:00→08:15或18小时扫描 | 稿件一般截至昨日 | 收集和使用分离；Edition冻结新闻/行情截点；当晨收的新信息可暂存不可偷用 |
| 冷启动 | 未详细处理 | 避免漏昨日日间信息 | 建议72小时首次回填、游标重叠续扫、积压显式显示；这些是可调工程预设 |
| 事件聚类 | 模糊标题阈值 | 去重看主事件/事实/结论 | 保留阈值作候选匹配，不把同一主题合并；阶段、数值冲突需拆分/关联 |
| 资料来源 | event_articles来源链 | 数字可追溯 | 增加fact_id和片段定位；媒体转载不改标Wind或原始公告 |
| 历史库 | 最近主题输入（如有） | 比较正文核心数据 | 导入授权正文/文件；只有标题则显示粒度受限；缺历史不得声称不撞题 |
| 成份关系 | 检索关键词 | 个别产品个别分析 | 画像与结构快照独立；路由词表不是持仓真值；不数箭头评关联 |
| 权限限制 | 不绕过访问限制 | 可落地可复用 | 访问能力探测、限速、人工/搜索降级；不生成未核实API路径 |
| 来源优先 | T1优先 | 不机械删重要线索 | 新增事实的origin_role；机构自有统计可作原始出处；转引需保留归属 |
| 下游合规 | metadata标记 | 不增加AI一轮合规 | 可用事实区做确定性字段过滤，待补/受限内容分区；不自动全文审稿 |
| 旧V5规则 | 旧净流入优先等 | 最新只用合适成交数据 | V5仅研究历史表达经验，不覆盖来源V1当前数据边界 |
| 接口能力 | .env留空 | Codex本地开发 | 明确开发助手≠运行时搜索/模型授权；none/fixture/人工材料均可启动 |
| 工程入口 | 先CLI，不UI | 看得见的线索板 | 先后端离线闭环与5源实采，再做单页；不用mock界面冒充完成 |
| 成本 | 12事件/20全文/4篇每事件 | 关注token与用时 | 全部保留，新增可调请求/token上限和实际计费状态，不写固定价格 |

## 不能从材料推出的结论

没有证据支持“26源已经稳定抓取”“所有URL现在可访问”“4产品画像等同最新持仓”“评分已通过历史验证”“5—10分钟在任意环境能达成”。V2没有外部核实这些结论。

原目录缺少的角色列入待补，不擅自补齐可执行网站接口。当前文档没有取得独立V6.4全文，仅沿用本次明确规则及V0.1中的已注明建议。

## 修改权限

用户明确要求的建议工具定位、人工采用、不得虚构来源、原来源初始范围与不绕访问限制不能由开发者自行取消。工程字段、预算阈值、UI框架和权重是试跑默认，可改但需版本记录和测试。任何新收费调用、私有资料外发、服务公开部署需要额外授权。
